Project: AfD-project
Date: 2026-04-28

What this project is doing
- The project builds reproducible news corpora from Nexis-style PDF archive exports.
- Current focus is corpus QC and conservative cleaning for event-oriented and related text datasets.
- The workflow extracts metadata and body text from PDF files, detects duplicates and low-value records, and produces keep/drop outputs without deleting originals.

Main corpus areas already worked on
- Corpora/Cologne
- Corpora/Chemnitz
- Corpora/Corrective Revelation
- Corpora/Main Corpus

Current protocol logic
- Each corpus keeps the original ZIP archive unchanged.
- PDFs are extracted into a raw_unarchive folder.
- A QC script reads all PDFs and writes:
  - qc/qc_articles.csv
  - qc/duplicate_groups.csv
  - qc/qc_summary.md
- A cleaning script reads the QC output and writes:
  - qc/article_registry.csv
  - qc/exclusion_log.csv
  - qc/clean_corpus_summary.md
- It also creates copy-based subsets:
  - clean_keep
  - excluded_drop
- Nothing is deleted automatically.

Important protocol rules
- Conservative by default: if uncertain, keep and note uncertainty.
- Standard drop categories:
  - duplicate_exact
  - duplicate_near
  - regional_variant
  - reader_letter
  - commentary_noncore
  - very_short_low_value
  - malformed
- Representative selection for duplicate/variant groups:
  - keep the most complete parse
  - then keep the longest text
  - if still tied, prefer the cleaner/general version over edition-like variants
  - if still tied, use deterministic filename ordering

Current folder conventions
- Corpora/Cologne, Corpora/Corrective Revelation:
  - one archive, one raw_unarchive, one qc, one clean_keep, one excluded_drop, one scripts folder
- Corpora/Chemnitz:
  - two datasets: core and extra
  - separate raw_unarchive_core/raw_unarchive_extra
  - separate qc/core and qc/extra
  - separate clean_keep_core / excluded_drop_core and clean_keep_extra / excluded_drop_extra
- Corpora/Main Corpus:
  - 156 month folders from 2013-01 to 2025-12
  - some months already processed manually/prototyped, including:
    - 2013-01
    - 2021-09
    - 2025-12

Main Corpus orchestration status
- Centralized orchestration is now implemented.
- Legacy per-month copied scripts still exist in a few month folders for historical/prototype traceability, but they are no longer required for running the workflow.

Implemented Main Corpus runner and protocol
- Orchestrator script:
  - Corpora/Main Corpus/run_main_corpus.py
- Shared internal protocol module:
  - Corpora/Main Corpus/_protocol/main_corpus_protocol.py
- Top-level run log:
  - Corpora/Main Corpus/main_corpus_run_log.csv
- Current runner behavior:
  - scans month folders named YYYY-MM
  - detects ZIP archives
  - creates raw_unarchive/qc/clean_keep/excluded_drop if missing
  - unpacks archives into raw_unarchive
  - runs the shared protocol for each month
  - skips already processed months by default (unless forced)
  - continues on month-level errors and records status in the top-level CSV log
- Current CLI controls:
  - --only 2021-09
  - --start 2013-01
  - --end 2025-12
  - --rerun
  - --reextract
  - --skip-existing

Operational expectations for the orchestrator
- Idempotent reruns
- Sequential processing by default
- Clear per-month status logging
- Continue on error and log the failure
- No permanent deletion of source material

Environment notes
- Preferred environment: conda env ds_env
- Typical run style:
  - conda run -n ds_env python "Corpora\Main Corpus\run_main_corpus.py"
- VS Code can accidentally use the wrong interpreter if the selected Python is not ds_env.

What a new chat should understand immediately
- This is not just ad hoc cleaning; it is a reproducible corpus-construction workflow.
- Preserve archives, extract to raw_unarchive, generate QC outputs, generate exclusion log, create keep/drop copies.
- Main Corpus now has a single automated runner with centralized protocol logic; future work should build on this shared entry point instead of month-specific scripts.
